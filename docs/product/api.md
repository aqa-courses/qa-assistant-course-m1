# REST API

Полная схема — на `/docs` (OpenAPI). Аутентификация: `POST /api/login` → `{"token": ..., "user": ...}`, дальше заголовок `Authorization: Bearer <token>`. Токен — тот же, что cookie сессии.

| Метод и путь | Что делает |
|---|---|
| `POST /api/login` | вход; 401 — неверные данные, 403 — блокировка |
| `GET /api/me` | текущий пользователь |
| `GET /api/products` | товары; `q`, `category`, `min_price`, `max_price`, `sort` как в каталоге |
| `GET /api/products/{id}` | один товар |
| `GET /api/cart` | корзина со сводкой |
| `POST /api/cart/items` | добавить: `{"product_id", "qty"}`; в ответе `note`, если сработал лимит |
| `PATCH /api/cart/items/{id}` | задать количество: `{"qty"}` |
| `DELETE /api/cart/items/{id}` | удалить строку |
| `POST /api/cart/promo` | применить промокод: `{"code"}` |
| `DELETE /api/cart/promo` | снять промокод |
| `POST /api/orders` | оформить: `{"address"}` → `201 {"order_id"}` |
| `GET /api/orders` | заказы пользователя |

Суммы в ответах — в рублях, числом (`2540.0`). Правила те же, что в интерфейсе: лимиты, промокоды и проверки оформления описаны в соответствующих спецификациях. Ошибки — `{"detail": "текст"}` с тем же текстом, что в интерфейсе.

Ограничения частоты запросов нет. Версионирования API нет, обратная совместимость не гарантируется.
