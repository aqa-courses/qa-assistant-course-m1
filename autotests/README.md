# Автотесты Shoplite

15 e2e-тестов на Playwright + TypeScript. С ними работают агенты курса: разбирают падения, чинят локаторы, ищут непокрытое.

## Запуск

```bash
# все команды из папки autotests; стенд должен работать на localhost:8000 (см. ../shoplite)
npm ci
npx playwright install chromium
npx playwright test
npx playwright show-report
```

Другой адрес стенда: `SHOPLITE_URL=http://host:port npx playwright test`, в PowerShell `$env:SHOPLITE_URL = "http://host:port"` перед запуском. Браузер из системы вместо скачанного: `PW_CHANNEL=chrome`.

## Соглашения

- **`@id:N`** у каждого теста означает номер тест-кейса в `fixtures/testcases.yaml`. По нему агенты связывают упавший тест с кейсом. `@smoke` помечает короткий набор.
- **Локаторы только `getByTestId`**, атрибут `data-test`. Никаких CSS-классов и XPath.
- **Данные через API, проверки через UI.** Логин и корзина готовятся фикстурами `loginAs` и `api` из `tests/fixtures.ts`, тест проверяет только то, что видит пользователь.
- **Каждый тест начинается с `POST /__reset`**, поэтому тесты идут в один поток.
- **Без ретраев и с короткими таймаутами (3 с)**: ретраи прячут флейки, а нам нужно их видеть.

## Что ломают флаги стенда

| Флаг | Падает | Как выглядит |
|---|---|---|
| `UI_VERSION=2` | все 15 | `element(s) not found` по `getByTestId` |
| `BUG_CART_TOTAL=1` | `@id:10` | итог больше ожидаемого на сумму скидки |
| `DB_DOWN=1` | все 15 | страница ошибки, API 503 |
| `FLAKY_SEARCH=1` | 0–2 из `@id:4–6`, от прогона к прогону по-разному | таймаут клика по «Найти» |
| `FEATURE_WISHLIST=1` | ничего | тесты зелёные, а фича не покрыта |

## CI

`.github/workflows/e2e.yml` в корне репозитория поднимает стенд в Docker и прогоняет тесты. Ручной запуск (Run workflow) принимает флаги поломок, так курс получает красные прогоны по запросу. Результаты (`results/results.json`, трейсы, HTML-отчёт) сохраняются артефактом `e2e-results`.
