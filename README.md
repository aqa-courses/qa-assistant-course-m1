# QA-ассистент на Google ADK — учебный репозиторий

Репозиторий курса: за 9 модулей вы собираете ассистента QA-инженера на [Google ADK](https://adk.dev/). Ассистент разбирает падения CI, чинит автотесты, триажит обращения поддержки и работает в продакшене. Всё — на учебном магазине Shoplite, который можно ломать по команде.

## Кому подходит и сколько времени займёт

Нужен уверенный Python: `async`/`await`, декораторы, типы, pytest. Если вы пишете автотесты на Java или TypeScript, а Python знаете по скриптам, курс пройти можно, но закладывайте больше времени. Местами без скидок нужны `asyncio.gather`, `asyncio.to_thread`, пул с временем жизни (модуль 3) и ASGI-middleware (модуль 8).

Сколько времени — пока оценка по объёму уроков и кода, а не замер: модули 1–2 вместе 7,5–13 часов, дальше по модулю 3–9 часов, весь курс — около 35–60 часов. Больше всего уходит на модули 4 и 8 и на живые проверки. Строки кода в заданиях («150–200 строк») — это объём, а не время: вместе с чтением урока, отладкой и живыми проверками модуль занимает несколько вечеров, а не один.

## Как проходить курс

Сначала один раз подготовьте всё нужное (раздел «Подготовка» ниже): форк, токен GitHub, ключ Claude, стенд. Дальше — модули по порядку, с первого по девятый. Каждый модуль проходится одинаково:

1. **Урок — [`modules/mNN/lesson.md`](modules/m01/lesson.md).** Читайте первым: как устроено то, что вы будете писать, история из реального проекта и подвохи, на которых застревают.
2. **Задания — [`modules/mNN/README.md`](modules/m01/README.md).** Что уже есть в заготовке, что написать и какие тесты это проверяют. Где нужна теория, задание ссылается на раздел урока.
3. **Код.** Решайте задания, пока `pytest tests/unit` не станет зелёным. Тесты не тратят токены: вместо Claude в них отвечает модель по сценарию.
4. **Вживую.** Пройдите чек-лист в конце урока: агенты в `adk web` на настоящей модели и стенде.
5. **Пулл-реквест в свой форк.** Автопроверка в GitHub Actions должна быть зелёной. Ответы на вопросы из заданий и таблицы замеров — в описание PR.

Застряли — сравните с эталоном в ветке `mNN-solution`. Подсматривайте после своей попытки: главное в модуле — подвохи, которые находишь сам.

Курс рассчитан на самопроверку. Код проверяют тесты. Где задание просит написать что-то в описании PR — ответить на вопрос, сравнить замеры, — в ветке решения есть `modules/mNN/answers.md`: эталонные ответы, наши замеры и то, что стоит проверить в своём решении глазами, потому что тесты этого не видят. Код-ревью ваших пулл-реквестов — платная опция.

### Ветки

Каждый модуль — пара веток: `mNN-start` — заготовка, код с `TODO` и тесты, которые пока падают; `mNN-solution` — эталонное решение. Ваш код копится в своей ветке `work`, а на каждый модуль заводится ветка для пулл-реквеста:

Что лежит в папке `modules/`, зависит от ветки: в `mNN-start` и `mNN-solution` — модули с первого по `NN`. На GitHub открывается ветка по умолчанию, поэтому сначала вы видите не все модули. Нужный модуль — в списке веток над файлами: например, модуль 2 лежит в `m02-start`. В вашей ветке `work` он появится после `git merge origin/m02-start`.

```bash
# один раз, в клоне вашего форка
git switch -c work origin/m01-start
git push -u origin work

# модуль 1
git switch -c m01 work
#   урок → задания → pytest tests/unit → чек-лист урока
git push -u origin m01            # пулл-реквест m01 → work; автопроверка зелёная — Merge

# каждый следующий модуль, например второй
git switch work && git pull
git merge origin/m02-start        # заготовка модуля поверх вашего кода
git push
git switch -c m02                 # и дальше так же: пулл-реквест m02 → work
```

**Пулл-реквест — в свой форк, а не в репозиторий курса.** GitHub при создании PR из форка по умолчанию предлагает base repository — репозиторий курса и его ветку по умолчанию. Смените base repository на свой форк, а base — на `work`. Если открыть PR в репозиторий курса, ваш код и ответы увидят все, у кого есть доступ к курсу. Из терминала: `gh pr create --repo <ваш логин>/<ваш форк> --base work`.

Ветки `start` добавляют материалы своего модуля и не трогают файлы ваших заданий. Поэтому, если вы правили только то, что просили задания, слияние проходит без конфликтов. В пулл-реквест попадает только ваш код модуля.

Конфликт возможен, если вы меняли что-то сверх заданий. Чаще всего это `pyproject.toml`, если вы добавили свою зависимость, или `.env.example`. Что делать:

1. `git status` покажет файлы с конфликтом. В файле между `<<<<<<<` и `>>>>>>>` — две версии: ваша и из заготовки.
2. Обычно нужны обе: оставьте свою строку и строки заготовки, уберите маркеры.
3. `git add <файл> && git commit --no-edit`, затем `pytest tests/unit`: тесты прошлых модулей должны остаться зелёными.

Передумали — `git merge --abort` вернёт всё как было.

Модуль не получился, а двигаться дальше хочется — продолжите с эталона: `git switch -C work origin/mNN-solution && git push -f origin work`. Ваша попытка останется в ветке `mNN`.

## Подготовка

Нужны Python 3.11+, Docker, Node.js 24 (для автотестов) и аккаунт GitHub.

На Windows команды курса удобнее всего запускать в Git Bash: он ставится вместе с Git for Windows, и команды из README работают как есть. В PowerShell отличаются четыре вещи:

| bash | PowerShell |
|---|---|
| `cp .env.example .env` | `Copy-Item .env.example .env` |
| `. .venv/bin/activate` | `.venv\Scripts\Activate.ps1` |
| `RUN_AGENT_EVALS=1 pytest tests/eval` | `$env:RUN_AGENT_EVALS = "1"; pytest tests/eval` — переменная живёт до закрытия окна, убрать: `Remove-Item Env:RUN_AGENT_EVALS` |
| `curl` с JSON в одинарных кавычках | `curl.exe`, а JSON — из файла: `curl.exe -d "@body.json" ...` |

### Форк и токен GitHub

Агенты работают с вашим форком: читают его прогоны Actions и файлы, с модуля 2 заводят задачи, с модуля 4 открывают pull request'ы. Три настройки форка по умолчанию мешают курсу:

1. При создании форка снимите галочку «Copy the … branch only». Иначе в форк попадёт одна ветка из всех.
2. На вкладке Actions нажмите «I understand my workflows, go ahead and enable them». Без этого e2e не запустится, и агенту нечего будет разбирать. Автопроверка пулл-реквеста тоже не запустится, причём без ошибки. Открыли пулл-реквест раньше, чем включили Actions, — закройте его и откройте снова (Close pull request, затем Reopen).
3. Settings → General → Features: включите Issues. С ними работает `issues_agent` из модуля 2.

Форк приватный, но не только ваш. Его видит автор курса: GitHub даёт владельцу репозитория курса права на все его форки. Другие студенты ваш форк не видят. Ключи и токены в форк не коммитьте — они лежат в `.env`, который git не отслеживает. Форк существует, пока у вас есть доступ к курсу: если доступ отозван, GitHub удаляет форк, и остаётся только ваш локальный клон.

Токен — fine-grained (Settings → Developer settings → Fine-grained tokens), с доступом только к форку. Права растут по модулям, можно сразу выдать их на весь курс:

| Модули | Права токена |
|---|---|
| 1 | Actions: read, Contents: read |
| 2–3 | плюс Issues: read and write |
| 4–9 | плюс Contents: read and write, Pull requests: read and write |

### Если вы прошли модуль 1 в бесплатном репозитории

Полный курс — отдельный репозиторий, и форк у него будет второй. Решать модуль 1 заново не нужно: перенесите свой код из первого форка.

```bash
# в клоне нового форка
git remote add m1 https://github.com/<ваш логин>/<форк бесплатного модуля>.git
git fetch m1
git switch -c work origin/m01-start
git checkout m1/m01 -- assistant      # m01 — ветка, в которой вы писали модуль 1
git commit -m "Модуль 1 из бесплатного репозитория"
pytest tests/unit                     # должен быть зелёным, как в первом форке
git push -u origin work
```

Дальше — с модуля 2: `git merge origin/m02-start`, как в разделе «Ветки». Не хотите переносить — начните с эталона первого модуля: `git switch -c work origin/m01-solution`.

Агенты должны смотреть в новый форк:

- в `.env` замените `GITHUB_REPO` на `<ваш логин>/<новый форк>`;
- токен привязан к репозиториям, которые вы выбрали при выпуске. Добавьте в него новый форк (Settings → Developer settings → Fine-grained tokens → ваш токен → Repository access) или выпустите новый. Со старым токеном агенты получат от GitHub 404;
- права токена для модулей 2–9 — в таблице выше.

### Ключ Claude

Ключ создаётся в консоли Claude: [platform.claude.com](https://platform.claude.com/settings/keys). API доступен не во всех странах — проверьте свою по [списку](https://www.anthropic.com/supported-countries) до пополнения баланса. Бесплатного уровня у API нет: пополните баланс на несколько долларов, на весь курс этого хватит с запасом (раздел «Сколько стоит модель»).

### Окружение

```bash
git clone https://github.com/<ваш логин>/<ваш форк>.git && cd <ваш форк>
cp .env.example .env              # ANTHROPIC_API_KEY, GITHUB_REPO, GITHUB_TOKEN
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

python scripts/doctor.py           # проверка окружения, форка и токена

docker build -t shoplite shoplite && docker run --rm -p 8000:8000 shoplite   # стенд на :8000
adk web --port 8080 assistant/agents                                          # чат с агентами на :8080
```

`scripts/doctor.py` ничего не меняет и не тратит токены. Он проверяет Python, Docker и Node.js, заполнен ли `.env`, принят ли ключ Claude, видит ли токен форк, включены ли в форке Actions и Issues и скопировались ли все ветки. На каждую проблему — строка «НЕТ» и что сделать.

## Сколько стоит модель

Автопроверка токенов не тратит. Токены уходят, только когда вы сами говорите с агентом в `adk web` или запускаете eval. Все агенты по умолчанию работают на Claude Haiku 5.5. Всё, что задания просят сделать с живой моделью, по замеру стоит на весь курс до $0,15. Отладка и эксперименты сверх этого стоят столько же за каждый раз, и нескольких долларов на них хватит.

Свой расход видно во вкладке State в `adk web` (`usage:total_tokens`) и в разделе Usage консоли Claude. Зациклившийся агент остановится на лимите сессии `SESSION_TOKEN_BUDGET` (1,5 млн токенов), а не на вашем счёте.

Курс рассчитан на Claude, но провайдера можно сменить одной переменной `AGENT_MODEL`: Gemini, DeepSeek, Ollama или любой сервер с OpenAI-совместимым API. Замер по модулям, лимиты и то, какие модели проверены вживую, — в [docs/models.md](docs/models.md).
