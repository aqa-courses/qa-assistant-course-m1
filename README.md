# QA-ассистент на Google ADK — модуль 1 бесплатно

Это первый модуль курса «AI-ассистент для QA на Google ADK»: за 9 модулей вы собираете ассистента QA-инженера на [Google ADK](https://adk.dev/) и Claude. Ассистент разбирает падения CI, чинит автотесты, триажит обращения поддержки и работает в продакшене. Всё — на учебном магазине Shoplite, который можно ломать по команде.

Модуль 1 здесь целиком: урок, задания, автопроверка и эталонное решение.

## Модуль 1. Основы ADK

Первый агент, `github_agent`: читает прогоны GitHub Actions, логи упавших джоб и файлы репозитория и отвечает, почему упал прогон. По дороге — то, о чём молчат туториалы: повторы и таймауты вызовов модели, учёт токенов и бюджет на сессию, обрезка огромных ответов инструментов и синхронный инструмент, который вешает весь сервер. Задания — в [modules/m01/README.md](modules/m01/README.md), урок — в [modules/m01/lesson.md](modules/m01/lesson.md).

```bash
git switch m01-start
# решаете задания из modules/m01/README.md, пока не позеленеет:
pytest tests/unit
```

- `m01-start` — заготовка: код с `TODO` и тесты, которые пока падают;
- `m01-solution` — эталонное решение. Подсматривать можно, но после своей попытки.

## Быстрый старт

Нужны Python 3.11+, Docker, Node.js 24 (для автотестов) и ключ Claude API ([platform.claude.com](https://platform.claude.com/settings/keys)). API доступен не во всех странах — проверьте свою по [списку](https://www.anthropic.com/supported-countries) до пополнения баланса. Бесплатного уровня у API нет: пополните баланс на несколько долларов, на весь курс этого хватит с запасом.

```bash
cp .env.example .env              # ANTHROPIC_API_KEY, GITHUB_REPO, GITHUB_TOKEN
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e ".[dev]"

docker build -t shoplite shoplite && docker run --rm -p 8000:8000 shoplite   # стенд на :8000
adk web --port 8080 assistant/agents                                          # чат с агентами на :8080
```

### Форк и токен GitHub

Агенты работают с вашим форком: читают его прогоны Actions и файлы, с модуля 2 заводят задачи, с модуля 4 открывают pull request'ы. Три настройки форка по умолчанию мешают курсу:

1. При создании форка снимите галочку «Copy the … branch only». Иначе в форк попадёт одна ветка из всех.
2. На вкладке Actions нажмите «I understand my workflows, go ahead and enable them». Без этого e2e не запустится, и агенту нечего будет разбирать.
3. Settings → General → Features: включите Issues. С ними работает `issues_agent` из модуля 2.

Токен — fine-grained (Settings → Developer settings → Fine-grained tokens), с доступом только к форку. Права растут по модулям, можно сразу выдать их на весь курс:

| Модули | Права токена |
|---|---|
| 1 | Actions: read, Contents: read |
| 2–3 | плюс Issues: read and write |
| 4–9 | плюс Contents: read and write, Pull requests: read and write |

## Сколько стоит модель

Автопроверка не тратит токены: вместо Claude в тестах работает `ScriptedLlm`, который отвечает по сценарию. Токены тратятся только когда вы сами говорите с агентом в `adk web`.

Все агенты по умолчанию работают на Claude Haiku 5.5: $0,10 за миллион входных токенов и $0,50 за миллион выходных. Агенту, которому этого мало, можно дать Claude Sonnet 5.5 ($2 / $10) одной переменной: `AGENT_MODEL_<ИМЯ_АГЕНТА>=claude-sonnet-5-5`. Каким агентам это нужно, вы проверите на eval в модуле 7.

| 2 | 5 вопросов к `fat_agent` и те же 5 к `root` | 469 тыс. | 0,018 | 0,018 |
| 3 | `github_agent` через MCP и через REST, по 2 вопроса; `explorer_agent` в двух сессиях | 225 тыс. | 0,012 | 0,012 |

| 5 | разбор четырёх упавших прогонов (по флагу на каждый) и «заведи баг по прогону» | 19 тыс. | 0,002 | 0,003 |
| 6 | офлайн-eval `--limit 30 --repeat 2` дважды: с grounding и без | 467 тыс. | 0,061 | 0,068 |

| 9 | разговор с токеном в сообщении; автоматизация кейса в песочнице; триаж задачи с внедрённой картинкой | 160 тыс. | 0,008 | 0,009 |
| **Курс** | | **2,4 млн** | **0,13** | **0,15** |

Оговорки к замеру:

- **Модули 6 и 7.** В одном из повторов модель примерно час отвечала не по схеме, и прогон eval оборвался (модуль 6, раздел «Офлайн-оценка»). Поэтому для них взяты только полные прогоны той же версии кода — шесть и пять.
- **Модуль 9.** Разговор замерен трижды. Автоматизация кейса стоит столько же, сколько в модуле 4: песочница меняет только то, где запускается тест, а не то, что видит модель. Триаж посчитан по среднему вызову из замера модуля 6.
- **Без кэша** тот же минимум стоил $0,28–0,30.

Всё, что вы делаете сверх минимума, — отладка, эксперименты, повторные прогоны — стоит столько же за каждый раз. Самые дорогие действия:

- прогон офлайн-eval триажа — $0,030;
- починка теста `healing_agent` — до $0,017;
- разговор с `root` из 5 вопросов — $0,012;
- eval маршрутизации — $0,0015.

Sonnet мы не замеряли. По цене токена он в 20 раз дороже: один прогон офлайн-eval триажа на нём стоил бы около $0,6.

Свой расход смотрите во вкладке State в `adk web` (`usage:total_tokens`) и в разделе Usage консоли Claude.

### Лимиты

- `SESSION_TOKEN_BUDGET` — лимит на сессию, по умолчанию 1 500 000. Самая длинная обязательная сессия — починка теста в модуле 4, до 714 тыс. токенов: каждый снимок страницы остаётся в истории, а каждый вызов модели заново отправляет всю историю. Лимит вдвое больше неё. Целиком он стоит на Haiku около $0,16 без кэша и заметно меньше с кэшем. Зациклившийся агент остановится на нём, а не на вашем счёте.
- `USER_DAILY_TOKENS` (модуль 8) — дневной лимит пользователя, по умолчанию 2 000 000: вдвое больше, чем весь самый тяжёлый модуль (модуль 4, до 865 тыс.).

## Другие модели

Курс рассчитан и замерен на Claude: цифры выше и пороги eval в модуле 7 получены на Haiku 5.5. Ассистент при этом не привязан к Claude — провайдера выбирает имя модели:

| `AGENT_MODEL` | Куда идут запросы | Ключ в `.env` |
|---|---|---|
| `claude-haiku-5-5` | Claude API, по умолчанию | `ANTHROPIC_API_KEY` |
| `gemini-3.5-flash-lite` | Gemini API | `GOOGLE_API_KEY` |
| `deepseek/deepseek-flash` | DeepSeek | `DEEPSEEK_API_KEY` |
| `ollama/qwen3:4b` | Ollama на вашей машине | не нужен |
| `ollama/deepseek-v4.1-flash` | Ollama Cloud: `OLLAMA_BASE_URL=https://ollama.com/v1` | `OLLAMA_API_KEY` |
| `openai/<модель>` | любой сервер с OpenAI-совместимым API | `OPENAI_BASE_URL`, `OPENAI_API_KEY` |

Имя задаётся и для отдельного агента: `AGENT_MODEL_<ИМЯ_АГЕНТА>`. Агенты могут работать у разных провайдеров одновременно.

Вживую проверены Gemini и DeepSeek через Ollama Cloud — замеры ниже. Локальная Ollama, API самого DeepSeek и остальные OpenAI-совместимые серверы проверены только автотестами на поддельном сервере, без настоящей модели.

Тот же минимум без модуля 4 на Claude Haiku стоит около $0,11: Gemini тратит почти вдвое меньше токенов, но токен у него дороже. Ограничений по числу запросов (ошибка 429) замер не встретил ни разу.

**Модуль 4 на `gemini-3.5-flash-lite` проходит не всегда.** Мы запускали его четыре раза: три повтора и пробный прогон перед ними.

- Починка теста `healing_agent` удалась трижды: 197, 335 и 757 тыс. токенов, $0,03–0,08. В четвёртый раз агент не остановился и дошёл до предела ADK в 500 вызовов модели.
- «Сделай `@id:10` зелёным» — три раза из трёх агент отказался ослаблять проверку и назвал баг в магазине.
- Автоматизация кейса удалась дважды ($0,02 и $0,05), в третий раз агент тоже не остановился.

В замере лимит на сессию был снят, поэтому две зациклившиеся сессии израсходовали 99 и 38 млн токенов — около $4 и $1,7. С лимитом курса `SESSION_TOKEN_BUDGET` в 1 500 000 они пересекли бы его на 66–69-м вызове, потратив $0,13–0,15. Это расчёт по записанным вызовам: сам обрыв на лимите с Gemini мы не проверяли. Не поднимайте лимит, если проходите модуль 4 на Gemini. Более сильную модель, например `gemini-3.8-flash`, на этом модуле мы не замеряли.
