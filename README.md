# QA-ассистент на Google ADK: учебный репозиторий

Репозиторий курса: за 9 модулей вы собираете ассистента QA-инженера на [Google ADK](https://adk.dev/). Ассистент разбирает падения CI, чинит автотесты, разбирает обращения поддержки и работает в продакшене. Всё это вы делаете на учебном магазине Shoplite, который можно ломать по команде.

## Кому подходит и сколько времени займёт

Нужен уверенный Python: `async`/`await`, декораторы, типы, pytest. Если вы пишете автотесты на Java или TypeScript, а Python знаете по скриптам, курс пройти можно, но закладывайте больше времени. Местами без скидок нужны `asyncio.gather`, `asyncio.to_thread`, пул с временем жизни (модуль 3) и ASGI-middleware (модуль 8). ADK есть и для Java, Kotlin, TypeScript и Go. Что из курса переносится на ваш язык и где на нём работает Claude, разобрано в уроке 1, раздел «ADK на других языках».

Время пока оценено по объёму уроков и кода, замера ещё не было: модули 1–2 вместе 8–13 часов, каждый следующий от 3,5–5,5 часа (модули 6 и 7) до 6–10,5 часа (модуль 4), весь курс около 40–68 часов. Больше всего уходит на модули 4, 5 и 8 и на живые проверки. Строки кода в заданиях («около 200 строк») показывают объём эталонного решения без пустых строк и комментариев. Времени они не показывают: вместе с чтением урока, отладкой и живыми проверками модуль занимает несколько вечеров.

## Как проходить курс

Сначала один раз подготовьте всё нужное (раздел «Подготовка» ниже): форк, токен GitHub, ключ Claude, стенд. Дальше проходите модули по порядку, с первого по девятый. Каждый модуль проходится одинаково:

1. **Урок: [`modules/mNN/lesson.md`](modules/m01/lesson.md).** Читайте первым: как устроено то, что вы будете писать, история из реального проекта и подвохи, на которых застревают.
2. **Задания: [`modules/mNN/README.md`](modules/m01/README.md).** Что уже есть в заготовке, что написать и какие тесты это проверяют. Где нужна теория, задание ссылается на раздел урока.
3. **Код.** Решайте задания, пока `pytest tests/unit` не станет зелёным (с модуля 7 запускайте `pytest tests`: задания модуля 7 проверяются в `tests/eval`). Тесты не тратят токены: вместо Claude в них отвечает модель по сценарию.
4. **Вживую.** Пройдите раздел «Проверка вживую» в README модуля: агенты на настоящей модели и стенде. Чек-лист в конце урока повторяет его пунктами, чтобы отметить сделанное.
5. **Пулл-реквест в свой форк.** Автопроверка в GitHub Actions должна быть зелёной. Ответы на вопросы из заданий, на три вопроса раздела «Проверьте понимание» и таблицы замеров впишите в описание PR.

После модуля 9 идёт финальный проект «флаки или регрессия»: задача без заготовки и пошаговых инструкций, критерии приёмки и защита архитектуры в `ARCHITECTURE.md`. Постановка лежит в `modules/final/README.md` и приходит вместе с модулем 9. Эталонного решения у него нет, и в оценку часов курса он не входит. Вместе с ним приходит задание по желанию `modules/a2a/README.md`: агент на Java, которого `root` зовёт по протоколу A2A.

В README модуля работа бывает трёх видов:

- **Задания** идут по порядку, их проверяют тесты.
- **Домашнее задание** тоже обязательно, но подсказок в нём меньше: это самая самостоятельная часть модуля. Если к нему есть тесты, без него автопроверка красная. Если тестов нет, результатом служит ответ или замер в описании PR.
- **По желанию**: эту часть не проверяют ни тесты, ни чек-лист. Можно пропустить.

Если застряли, сравните с эталоном в ветке `mNN-solution`. Подсматривайте после своей попытки: польза модуля в подвохах, которые вы находите сами.

Курс рассчитан на самопроверку. Код проверяют тесты. Где задание просит написать что-то в описании PR (ответить на вопрос, сравнить замеры), в ветке решения есть `modules/mNN/answers.md`: эталонные ответы, наши замеры и то, что стоит проверить в своём решении глазами, потому что тесты этого не видят. Код-ревью ваших пулл-реквестов входит в тариф с ревью. Вопросы по окружению и заданиям задавайте в закрытом чате студентов в Telegram: ссылка на него приходит вместе с доступом к курсу.

### С ИИ-помощником

Проходить курс с Claude Code, Cursor или другим помощником можно и стоит: он объяснит незнакомый Python, починит окружение и расскажет, что проверяет упавший тест. Но помощник с доступом к репозиторию сделает тесты зелёными за несколько минут, и вы ничего не узнаете. Главное в каждом модуле: подвох, который вы находите сами.

Поэтому в корне лежит [AGENTS.md](AGENTS.md): правила, по которым помощник работает наставником. Он подсказывает по нарастающей, не пишет решение задания целиком, не заглядывает в ветки `solution` и не правит тесты. Claude Code, Cursor и Codex читают этот файл сами. Другому помощнику скажите в начале разговора: «прочитай AGENTS.md и следуй ему».

`AGENTS.md` остаётся просьбой к помощнику, защиты от подсматривания он не даёт. Эталоны лежат в ветках `mNN-solution` вашего форка. Помощник, который файл не прочитал или которого попросили его не соблюдать, откроет их без помех, а проверки, кто и когда смотрел эталон, в курсе нет. Файл помогает не наткнуться на решение случайно, остальное зависит от вас.

Как спрашивать помощника, чтобы учиться:

- «Объясни, что проверяет этот тест и почему он падает. Код не пиши.»
- «Дай подсказку, в какую сторону думать.»
- «Я написал так. Что здесь не так?»
- «Объясни эту конструкцию Python, я пишу на Java.»

Окружение, синтаксис и шаблонный код отдавайте помощнику спокойно. Задания с подвохом делайте сами.

### Ветки

У каждого модуля две ветки. В `mNN-start` лежит заготовка: код с `TODO` и тесты, которые пока падают. В `mNN-solution` лежит эталонное решение. Ветка `main` содержит эталон всего курса вместе с ответами `answers.md`: работайте в `work`, а `main` не открывайте до конца курса.

Что лежит в папке `modules/`, зависит от ветки: в `mNN-start` и `mNN-solution` там модули с первого по `NN`. На GitHub открывается ветка по умолчанию, поэтому сначала вы видите не все модули. Нужный модуль ищите в списке веток над файлами: например, модуль 2 лежит в `m02-start`. В вашей ветке `work` он появится после `git merge origin/m02-start`.

Ваш код копится в своей ветке `work`, а на каждый модуль заводится ветка для пулл-реквеста:

```bash
# один раз, в клоне вашего форка (как его сделать — раздел «Подготовка» ниже)
git switch -c work origin/m01-start
git push -u origin work

# модуль 1
git switch -c m01 work
#   урок → задания → pytest tests/unit → чек-лист урока
git push -u origin m01            # пулл-реквест m01 → work; автопроверка зелёная — Merge

# каждый следующий модуль, например второй
git switch work && git pull
git merge origin/m02-start        # заготовка модуля поверх вашего кода
pip install -e ".[dev]" -c constraints.txt   # модуль мог добавить зависимости
git push
git switch -c m02                 # и дальше так же: пулл-реквест m02 → work
```

**Пулл-реквест открывайте в свой форк.** GitHub при создании PR из форка по умолчанию предлагает в качестве base repository репозиторий курса и его ветку по умолчанию. Смените base repository на свой форк, а base на `work`. Если открыть PR в репозиторий курса, ваш код и ответы увидят все, у кого есть доступ к курсу. Из терминала: `gh pr create --repo <ваш логин>/<ваш форк> --base work`.

Ветки `start` добавляют материалы своего модуля и не трогают файлы ваших заданий. Поэтому, если вы правили только то, что просили задания, слияние проходит без конфликтов. В пулл-реквест попадает только ваш код модуля.

Конфликт возможен, если вы меняли что-то сверх заданий. Чаще всего это `pyproject.toml`, если вы добавили свою зависимость, или `.env.example`. Что делать:

1. `git status` покажет файлы с конфликтом. В файле между `<<<<<<<` и `>>>>>>>` стоят две версии: ваша и из заготовки.
2. Обычно нужны обе: оставьте свою строку и строки заготовки, уберите маркеры.
3. `git add <файл> && git commit --no-edit`, затем `pytest tests/unit`: тесты прошлых модулей должны остаться зелёными.

Если передумали, `git merge --abort` вернёт всё как было.

Автор может поправить заготовку уже после того, как вы сделали форк. Сам форк не обновляется: `git pull` берёт только из него. Чтобы получить исправление, на GitHub откройте в форке нужную ветку `mNN-start` и нажмите Sync fork. Потом в `work` выполните `git fetch origin` и, как обычно, `git merge origin/mNN-start`: без `fetch` Git не увидит исправления и ответит `Already up to date`.

Если модуль не получился, а двигаться дальше хочется, продолжите с эталона: `git switch -C work origin/mNN-solution && git push -f origin work`. Ваша попытка останется в ветке `mNN`.

## Подготовка

Нужны Python 3.11+, Docker, Node.js 24 (для автотестов, а с модуля 3 и для браузера агента) и аккаунт GitHub.

**На Windows сначала одна проверка.** Выполните `python -c "import ssl; ssl.create_default_context()"`. Если команда упала с `[ASN1] nested asn1 error` или `cadata does not contain a certificate`, Python на этом компьютере не может прочитать хранилище сертификатов Windows, и курс в обычном окружении Windows не пойдёт. Тогда сразу переходите в WSL 2 и клонируйте форк уже туда: почему так и как устроить окружение, написано в конце раздела «Окружение». Если команда ничего не вывела, всё в порядке.

На Windows команды курса удобнее всего запускать в Git Bash: он ставится вместе с Git for Windows, и команды из README работают как есть. Отличается одна: виртуальное окружение в Git Bash активирует `. .venv/Scripts/activate`. В PowerShell отличаются пять вещей:

| bash | PowerShell |
|---|---|
| `cp .env.example .env` | `Copy-Item .env.example .env` |
| `. .venv/bin/activate` | `.venv\Scripts\Activate.ps1`; если PowerShell запрещает скрипты, один раз выполните `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `RUN_AGENT_EVALS=1 pytest tests/eval` | `$env:RUN_AGENT_EVALS = "1"; pytest tests/eval`. Переменная живёт до закрытия окна, убрать её: `Remove-Item Env:RUN_AGENT_EVALS` |
| `curl` с JSON в одинарных кавычках | `curl.exe`, а JSON передайте из файла: `curl.exe -d "@body.json" ...` |
| `команда1 && команда2` | в PowerShell 7 работает как есть; встроенный в Windows PowerShell 5.1 его не понимает, там выполняйте команды по одной |

### Форк и токен GitHub

Агенты работают с вашим форком: читают его прогоны Actions и файлы, с модуля 2 заводят задачи, с модуля 4 открывают пулл-реквесты. Три настройки форка по умолчанию мешают курсу:

1. При создании форка снимите галочку «Copy the … branch only». Иначе в форк попадёт одна ветка из всех.
2. На вкладке Actions нажмите «I understand my workflows, go ahead and enable them». Без этого e2e не запустится, и агенту нечего будет разбирать. Автопроверка пулл-реквеста тоже не запустится, причём без ошибки. Если открыли пулл-реквест раньше, чем включили Actions, закройте его и откройте снова (Close pull request, затем Reopen).
3. Settings → General → Features: включите Issues. С ними работает `issues_agent` из модуля 2.

Форк приватный. Кроме вас, его видит автор курса: GitHub даёт владельцу репозитория курса права на все его форки. Другие студенты ваш форк не видят. Ключи и токены в форк не коммитьте: они лежат в `.env`, который git не отслеживает. Форк существует, пока у вас есть доступ к курсу: если доступ отозван, GitHub удаляет форк, и остаётся только ваш локальный клон.

Токен нужен fine-grained (Settings → Developer settings → Personal access tokens → Fine-grained tokens), с доступом только к форку. Права растут по модулям, можно сразу выдать их на весь курс:

| Модули | Права токена |
|---|---|
| 1 | Actions: read, Contents: read |
| 2–3 | плюс Issues: read and write |
| 4–9 | плюс Contents: read and write, Pull requests: read and write |

### Если вы прошли модуль 1 в бесплатном репозитории

Полный курс лежит в отдельном репозитории, и форк у него будет второй. Решать модуль 1 заново не нужно: перенесите свой код из первого форка.

```bash
# в клоне нового форка
git remote add m1 https://github.com/<ваш логин>/<форк бесплатного модуля>.git
git fetch m1
git switch -c work origin/m01-start
git checkout m1/m01 -- assistant      # m01 — ветка, в которой вы писали модуль 1
git commit -m "Модуль 1 из бесплатного репозитория"
pytest tests/unit                     # должен быть зелёным, как в первом форке
git push -u origin work
```

Дальше продолжайте с модуля 2: `git merge origin/m02-start`, как в разделе «Ветки». Если не хотите переносить, начните с эталона первого модуля: `git switch -c work origin/m01-solution`.

Агенты должны смотреть в новый форк:

- в `.env` замените `GITHUB_REPO` на `<ваш логин>/<новый форк>`;
- токен привязан к репозиториям, которые вы выбрали при выпуске. Добавьте в него новый форк (Settings → Developer settings → Personal access tokens → Fine-grained tokens → ваш токен → Repository access) или выпустите новый. Со старым токеном агенты получат от GitHub 404;
- права токена для модулей 2–9 указаны в таблице выше.

### Ключ Claude

Ключ создаётся в консоли Claude: [platform.claude.com](https://platform.claude.com/settings/keys). API доступен не во всех странах: проверьте свою по [списку](https://www.anthropic.com/supported-countries) до пополнения баланса. Бесплатного уровня у API нет: пополните баланс на несколько долларов, на весь курс этого хватит с запасом (раздел «Сколько стоит модель»).

### Окружение

```bash
git clone https://github.com/<ваш логин>/<ваш форк>.git && cd <ваш форк>
cp .env.example .env              # ANTHROPIC_API_KEY, GITHUB_REPO, GITHUB_TOKEN
python -m venv .venv && . .venv/bin/activate   # Git Bash на Windows: . .venv/Scripts/activate
pip install -e ".[dev]" -c constraints.txt   # проверенные версии библиотек

python scripts/doctor.py           # проверка окружения, форка и токена

docker build -t shoplite shoplite && docker run --rm -p 8000:8000 shoplite   # стенд на :8000, занимает терминал; нужен с модуля 3
adk web --port 8080 assistant/agents                                          # во втором терминале: чат с агентами на :8080
```

После установки заведите ветки `work` и `m01`: команды есть в разделе «Ветки» выше. Код заданий пишите в `m01`.

`-c constraints.txt` ставит ровно те версии библиотек, на которых курс проверен. `pyproject.toml` задаёт диапазоны, и без этого файла два студента в разные дни получили бы разные версии Anthropic SDK и OpenTelemetry, а с ними и разное поведение. Файл обновляет автор курса вместе с заготовками модулей, поэтому после `git merge origin/mNN-start` команда установки та же.

Стенд нужен с модуля 3. В модуле 1 агент читает прогоны Actions в форке, а там стенд поднимает сам workflow. Чтобы остановить стенд, нажмите Ctrl+C в его терминале. Модуль 4 запускает свой стенд с флагами: тогда сначала остановите обычный. Стенд песочницы модуля 9 живёт в своей сети Docker и обычному не мешает.

Запустить ассистента можно двумя способами. `adk web` запускает только агентов и их dev-интерфейс. `uvicorn --env-file .env assistant.app:app --port 8080` запускает всё приложение: агентов, тот же dev-интерфейс на `/dev-ui`, `/health`, с модуля 5 вебхук. Флаг `--env-file .env` обязателен: `adk web` читает `.env` сам, а приложение под uvicorn увидит его только при первом обращении к агенту, и вебхук, пришедший раньше, не найдёт секрета. Скрипты и eval, которые задания запускают через `python`, читают `.env` сами.

`scripts/doctor.py` ничего не меняет и не тратит токены. Запускайте его после каждого слияния заготовки. Он проверяет Python, установлены ли все зависимости из `pyproject.toml`, Docker и Node.js, заполнен ли `.env`, принят ли ключ Claude, видит ли токен форк, включены ли в форке Actions и Issues и скопировались ли все ветки. На каждую проблему он выводит строку «НЕТ» и пишет, что сделать. То, что понадобится позже, он отмечает «!» с номером модуля: например, Docker нужен с модуля 3, Issues с модуля 2, автотесты с модуля 4. До этого модуля такие строки можно оставить. Баланс ключа doctor не проверяет: ключ принимается и при нулевом балансе. Если первый живой ответ падает с ошибкой баланса, пополните его в консоли Claude.

Если doctor пишет, что Python не читает сертификаты системы (например, `[ASN1] nested asn1 error` или `cadata does not contain a certificate`), в хранилище сертификатов Windows лежит сертификат, который Python не может разобрать. Такие ставят, например, программы для электронной подписи и корпоративные прокси. Python на Windows читает это хранилище при каждом HTTPS-соединении, а ADK обращается к хранилищу уже при импорте, поэтому падают даже тесты без сети. `SSL_CERT_FILE` не помогает. Проходите курс в WSL 2: Python в Linux хранилище Windows не читает. Клонируйте форк в домашнюю папку WSL (`~`): папки Windows видны в WSL как `/mnt/c/...` через медленную файловую систему, и `pip install` там может идти десятки минут.

## Сколько стоит модель

Автопроверка токенов не тратит. Токены уходят, только когда вы сами говорите с агентом в `adk web` или запускаете eval. Все агенты по умолчанию работают на Claude Haiku 5.5. Всё, что задания просят сделать с живой моделью, стоит на весь курс до $0,14: это замер по всем девяти модулям (подробности в [docs/models.md](docs/models.md)). Отладка и эксперименты сверх этого стоят столько же за каждый раз, и нескольких долларов на них хватит.

Свой расход видно во вкладке State в `adk web` (`usage:total_tokens`) и в разделе Usage консоли Claude. Зациклившийся агент остановится на лимите сессии `SESSION_TOKEN_BUDGET` (1,5 млн токенов) и не опустошит ваш баланс.

Курс рассчитан на Claude, но провайдера можно сменить переменной `AGENT_MODEL` и ключом этого провайдера в `.env`: Gemini, DeepSeek, Ollama или любой сервер с OpenAI-совместимым API. Замер по модулям, лимиты и то, какие модели проверены вживую, описаны в [docs/models.md](docs/models.md).
